# LiveBridge — 日英会议中文翻译

适用于现场研究室会议：本机麦克风连续采音，日语/英语自动识别，默认中文翻译。主界面是宽幅滚动双语对话，不再显示三个头像框或顶部大字幕。

## 启动 / 更新

```sh
cd lab-meeting-translator
.venv/bin/python -B app.py --web
```

首次安装：Python 3.11+，在虚拟环境中安装 requirements.txt；复制 .env.example 为 .env 并填写 OPENAI_API_KEY。密钥只在后端。

打开 http://127.0.0.1:8000 。代码更新后必须重启旧 Python 服务并刷新网页；先结束会议并导出记录，不要直接刷新正在录音的页面。可用 --port 8765 启动独立测试实例。默认仅监听本机；不要直接暴露到公网。

## 使用

1. 选择会议专题（不是发言语言）、输入设备，默认目标中文。
2. 允许麦克风并开始。日语、英语及同一句中的语言切换无需手动操作。
3. 原文按段保留，确认后结合前面六段上下文和本专题词库翻译。英语上下文用于消除日语术语歧义，不凭空改写原文。
4. “结束”停止采音后等待最后一段返回；“导出记录”导出所有已接收记录。“清空显示”只隐藏旧段落，不删除导出数据。
5. 新会议会重置当前页面的记录；请先导出。页面刷新或断线不会自动恢复录音，当前版本不将完整会议记录写入磁盘。
6. 朗读译文是浏览器语音合成，默认关闭，建议佩戴耳机。不是原来的翻译音频轨道。

“先查看界面与词库”不录音。模块自检使用 debug_artifacts/mixed.wav 合成日英音频，不访问麦克风，但正常服务上的自检会调用收费 API。

## 双栏会议界面

左侧约 65% 为实时双语记录，右侧为分段总结。顶部“采音状态”显示设备及处理状态，不占据总结栏。

- 左侧每段按时间顺序展示原文和译文，使用完整列宽；不显示人物编号、身份标签或相关设置。
- 默认“跟随最新”；向上滚动查看旧发言时停止跟随，勾选后回到最新。不再另设顶部大字幕或字幕开关。

- 默认每分钟更新当前草稿，每 5 分钟形成一个总结块；开始会议前可选每 1 分钟一段。按收到音频的时间分段，不依赖页面是否在前台。
- 结束会议后，不足一分钟的最后一段也会总结。“现在总结”可提前生成当前已有内容。
- 总结列出讨论内容、明确结论、待确认项；没有结论不强行生成。引用按钮可跳转到左侧对应记录。
- 跨时间边界的发言按结束时间归入一段，避免重复；补听原文本身仍可能包含重复内容。
- 左右独立滚动，右侧可取消跟随。窄屏上下分区，保留两种视图。
- 辅助分析使用独立、最多 2 个工作线程；忙/失败会提示，不等待它才采音或翻译。仍共享同一 API 项目的额度，不能承诺完全没有资源竞争。

## 两种纠正方式

### 左侧：用大致理解纠正发言

点击某段“纠错 / 补充”，输入你听懂的大意，不需要还原准确日语。可选连续 1–6 段或最近 6 段。系统按你的理解核对译文并说明依据，原始识别不被改写。修订可撤销；高级“确认完整原话”模式仍只允许针对一段。

### 右侧：注解或文件纠正整段总结

点击“注解 / 文件纠正这段总结”，可写注解，或主动选择一份照片（JPEG、PNG、WebP、HEIC / HEIF）、PDF、PPTX、DOCX、TXT、MD 文件（6 MB 以内）。HEIC 不区分扩展名大小写，在本机内存中解码、校正方向并转换为 JPEG，移除原图元数据后才送分析；最多 5000 万像素，最长边缩至 4096，多图仅处理主图。需安装 requirements.txt 中的 Pillow 和 pillow-heif。每份文件需要勾选发送到 OpenAI 的同意，不自动开启摄像头。Office 文件主要提取文本，图表建议导出 PDF；其他格式请先转换。文件通过内联数据发送，不在本地服务端保存，也不创建持久 Files API 上传。

注解入口不会因后台总结更新而禁用。打开编辑窗口期间暂停发起新的自动总结，录音与实时翻译继续；如果已有总结请求未完成，提交注解会显示等待提示，完成后继续核对。关闭窗口（包括 Esc）后恢复自动总结。

材料只作用于选定总结块。材料中有、发言中没有的内容单列为参考，不当成会议结论。修订保留原总结、依据，可撤销；之后更新仍会使用该块保留的依据。新材料术语只进入本专题候选词。

右侧修改不会自动改左侧。若发现相关字幕疑点，点击“查看相关字幕修订建议”，逐条确认后才应用。过期字幕版本的建议会拒绝覆盖。

总结、注解及字幕修订保存在当前页面内存，**刷新会丢失**；请用“导出记录”保存，导出包含总结与修订历史。专题词库是独立持久数据库，不等同于保存整场会议。


## 四套独立专题数据库

存放在 data/glossaries/：

| 专题 | 文件 | 初始术语数 |
| --- | --- | --- |
| 室内定位 | indoor.sqlite3 | 17 |
| 动物 | animals.sqlite3 | 12 |
| 生物实验 | biology.sqlite3 | 14 |
| HAR | har.sqlite3 | 12 |

初始词表是可编辑的起点，不能涵盖每个实验室的专有命名。专题不会自动混用。

- 每个条目保存英文/术语、日文、中文译法、别名、备注、状态和出现段数。
- 识别结果中发现的新缩写、片假名只进入“候选词”，不会自动作为可信提示。候选抽取不是完整的术语发现系统。
- 打开“专题词库”，补全中文/日文并确认后，才参与后续提示；也可新增、归档、搜索、JSON 导入导出。
- 新译文请求实时读取最新已确认术语；识别关键词在下一场会议生效。不会自动重译之前的记录。
- 同名修改有 revisions 审计记录；归档保留数据。导入按条保存，遇到无效条目停止并提示已经保存的数量。
- 更新词表属于检索/提示增强，不是自动微调模型，也不保证准确率会单调提高。
- 备份整个 data/glossaries 目录即可保存数据库和修订历史。JSON 导出仅包含当前条目，不包含历史。

### 历史会议词汇与口语记忆

- 2026-10-09 整理了既有候选词的标准日英中词义，按适用领域共享条目，保留原始计数和来源。词义经过整理不等于原始识别、发言身份或会议事实经过确认。疑似识别错误仍是候选，不强行扩展缩写或补专名。
- 每个专题库新增 `term_evidence`：记录来源 ID、来源类型和短上下文片段。新版本对同一来源 ID 去重；旧版本仅有计数的条目不能恢复历史全文。照片和录音来源分开标记，补听重叠单独标记，不把计数当作可靠的发言频率。
- `data/glossaries/memory/expressions.sqlite3` 保存通用口语的中文译法、语气边界和来源；只有当前原文命中的已整理词义进入翻译，不把历史会议摘录和姓名发送到翻译提示，也不把口头语作为 ASR 强制关键词。
- 可建立个人表达的手动归属档案。不从常见口头语推断身份，不恢复发言者识别；需要用户指认具体原话后才能关联。姓名与归属仅保存在被 Git 忽略的本地数据库。
- 新版本会在本地持久保存术语/已知口语命中附近的短文本，不保存完整逐字稿或原始录音。新发现的未知词仍仅进入候选。口语库不会自动从没有证据的内容扩写习惯表达。
- `.venv/bin/python -B curate_meeting_memory.py` 整理已有候选词，可重复运行；先通过 SQLite 在线备份保存原库，不覆盖已确认的用户修订。需要处理已授权的本地转写报告时，显式传入 `--record-report PATH`；个人档案名称可用 `--profile-name NAME` 指定。没有默认绑定任何人的姓名或会议录音。

## MacBook 现场采音与噪声

开始前可以选择处理模式；一场会议中不热切换，避免重建采音造成缺口。

- 默认“会议室”：轻度 80 Hz 高通，降低低频轰鸣，不设置丢弃弱声的音量门限。它不能分离重叠发言或消除房间混响。
- “原始对照”：关闭应用额外滤波；浏览器回声消除、自动增益仍请求开启，因此不是未经系统处理的硬件原始信号。
- “浏览器降噪”：额外请求浏览器降噪，可能削弱远处发言，只作为可选对照。采音状态显示浏览器实际报告的降噪、回声消除、增益设置；不支持或未报告的状态不当成已开启。
- “实验：底噪自适应分段”：在轻度高通基础上，使用滚动低分位电平估计底噪；使用下述实时断句规则。不会丢弃低于门限的音频。公开样本中没有稳定准确率收益，默认不启用。
- “采音状态”新增几乎无输入、弱输入、削顶提示。电平正常不等于人声清晰，更不能证明收音完整。页面能看到实际设备名；优先确认是 MacBook 内置麦克风，不是蓝牙耳机输入。
- 服务端强降噪保持关闭，避免和浏览器处理叠加。一次公开日语学会发言 A/B 中，`far_field` 反而增错；不能由此推断它对所有录音都无效。

诊断报告仅保留在本地，不随源码提交。轻度过滤不等于识别准确率已得到验证；远距离、多人重叠和术语仍需经授权的真实会议音频与人工文本验收。

## 模块与数据流

浏览器 AudioWorklet → 单声道 24 kHz PCM16 → 本机 WebSocket → gpt-live-transcribe 持续识别 → 按 item_id 保留原文 → gpt-4.1-mini 滚动文本翻译 → 同一段双语显示。

- static/pcm-encoder.js：跨音频块重采样、PCM16 编码；不依赖页面动画或切换标签页提交录音。
- meeting.py：音频帧立即发往识别服务，不再攒完整录音窗口。日英双语提示、low 延迟；不预选一种语言。当前段每约 1 秒取最新原文重新翻译；同一段原位替换，定稿优先于旧草稿，不堆积过时请求。服务请求耗时超过 1 秒时不会强行并发，不能保证端到端 1 秒。滚动翻译比仅定稿翻译增加 API 用量。
- 断句：至少 2 秒上下文，识别到句末标点且停顿约 350ms 时定稿；无句末时等待约 1 秒停顿。连续无停顿用 25 秒安全上限，仍有词中边界风险；不是语义模型级断句。RMS 只决定提交，不按音量丢帧。持续静音也会提交，增加用量且存在识别幻觉风险。
- 原文 14px、译文 18px，去掉重复标签和空内容占位；常见桌面窗口以约四段短对话为排版目标，长段落自然滚动。保留真实错误与纠错按钮；不再做身份/音色聚类或按人分行。
- 有能量但识别为空的片段，最多带前 8 秒真实音频补听一次；补听可能重复前文，界面明确标记，不假装逐词对齐。非空但漏词的结果尚不会自动触发补听。
- 结束时等待 AudioWorklet 尾帧（最多 10 秒，超时明确报错），比较浏览器发送与服务端接收字节数；后端等待识别和翻译结束后才确认关闭。上限切段仍可能切在词中间。
- 原文事件乱序返回时按提交顺序翻译；译文靠稳定 item_id 配对，不再靠单个“当前句子”或清空计时器。
- topics.py：持久词库、候选发现、修订历史。
- static/meeting-ui.js：设备选择、录音状态、字幕、错误及处理计数；static/glossary-ui.js：词库管理。
- 旧 /api/session、/api/transcription-session 仅为兼容保留；新页面不使用旧双 WebRTC 路径。
- app.py 不带 --web 时仍保留原有终端 ASR，不使用本次 Web 专题/翻译功能。

正常网页会议不将原始音频写入磁盘；音频和所需上下文会发送到 OpenAI。单独的诊断录音工具经授权会保存本地 WAV，不会自动删除。候选词、导出记录和诊断报告可能包含非公开内容，应按项目资料保护。

## 模块排查

侧栏（窄屏在主区显示关键状态）可以查看采音秒数、送识别秒数、提交/确认/翻译段数。

- 音量始终零：检查浏览器权限与所选麦克风。
- 采音增加但提交不增加：尚未定稿也应能看到增量原文/译文；无停顿时提交最多等待 25 秒。应重点对照“采音”和“已送识别”是否同步增长，长期没有文字需检查连接和错误提示。
- 提交增加、确认不增加：识别服务积压或连接异常。
- 原文正确但译文错误：检查专题、术语映射和上下文，不能通过改 UI 修复。
- 明确错误保留原文，不用“正在翻译”掩盖失败。
- 当前没有自动断线重放，也不能从混合单路录音恢复被麦克风漏掉或掩盖的发言。

## 提交前隐私检查

`.env.example` 仅保留空的 `OPENAI_API_KEY=`；实际密钥通过本地 `.env` 或环境变量提供。不要把密钥粘贴到源码、报告或提交信息中。

Git 默认忽略环境文件、数据库及备份、录音、上传文件、日志和本地诊断报告。提交前运行：

```sh
python3 scripts/check_staged_privacy.py
git diff --cached --stat
```

检查器核对暂存文件类型、常见密钥格式及本地环境中已配置的秘密值，发现问题时只报告文件位置，不输出秘密内容。它不能代替人工审阅，不要使用 `git add -f` 强行提交私人数据。
